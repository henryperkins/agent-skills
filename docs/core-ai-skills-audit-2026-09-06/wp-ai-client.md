- **[high]** `references/prompt-builder.md:134` — `esc_url( $part->getFile()->getDataUri() )` → `esc_url()` rejects any scheme not in `wp_allowed_protocols()` (`wp-includes/functions.php:7335`, no `data`) via `wp_kses_bad_protocol` and returns `''` (`wp-includes/formatting.php:4631-4636`); running 7.1's `esc_url()` on `data:image/png;base64,…` returns `""` (scratch `esc_url_harness.php`), so the multimodal example renders `<img src="">`. - **[high]** `references/prompt-builder.md:204-214` (echoed at `SKILL.md:38,214` and `scripts/detect_ai_client.mjs:135,212,218`) — "Loading it via Composer too will cause duplicate-class errors" + the `if ( ! function_exists( 'wp_ai_client_prompt' ) ) { require_once …/vendor/autoload.php; }` pattern → (a) wrong mechanism: Core registers a *lazy* `spl_autoload_register` loader for `WordPress\AiClient\` (`wp-includes/php-ai-client/autoload.php:13-44`) and Composer's loader is lazy too, so no class is ever declared twice; the real hazard is version/namespace mixing — Core's classes type-hint scoped `WordPress\AiClientDependencies\Psr\…` while standalone 1.4 uses `Psr\…`, and 1.4-only classes (e.g. `EmbeddingBuilder`) would load from the plugin copy against Core's 1.3.1 `ModelConfig` — which upstream itself describes as "PSR namespace conflicts with core's scoped dependencies" (`wp-ai-client-0.4.0/includes/AI_Client.php:57-59`); (b) the snippet gates the plugin's *entire* Composer autoloader (own PSR-4 classes, every other dependency) on one Core function, so on 7.0+ nothing under `vendor/` loads, and on < 7.0 the outcome depends on load order relative to the wp-ai-client plugin, which defines the same function (`wp-ai-client-0.4.0/functions.php:22-36`); (c) "Composer doesn't allow more granular conditional autoloading without splitting into two Composer setups" omits the standard remedy the skill recommends elsewhere (`SKILL.md:225`, `embedding-builder.md:10`): prefix/scope the SDK (Strauss/PHP-Scoper), or don't vendor it at all and gate on `class_exists( \WordPress\AiClient\AiClient::class )` as the official provider plugin does (`provider-anthropic-1.0.4/plugin.php:41`). → Fix: rewrite the section — always load `vendor/autoload.php`; never ship an unprefixed `wordpress/php-ai-client`; for 6.x support ship a prefixed copy or depend on the (deprecated) wp-ai-client plugin; use `class_exists()`/`function_exists()` only to pick the entry point — and change the script's note text.
