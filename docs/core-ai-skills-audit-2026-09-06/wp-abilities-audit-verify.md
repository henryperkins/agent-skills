## Findings

- **[low]** `audit/references/capability-gate-tracing.md:247-249` — "`wc_rest_check_post_permissions()` … wraps the same core machinery … the underlying mechanism is core's `map_meta_cap()`" → WooCommerce `wc-rest-functions.php:229-247` (trunk) maps `read` → `$post_type_object->cap->read_private_posts` and `create` → `cap->publish_posts`, `batch` → `cap->edit_others_posts`, then calls `current_user_can( $cap, $object_id )`; only `edit` (`cap->edit_post`) and `delete` (`cap->delete_post`) are meta caps that enter `map_meta_cap()`'s author branches. The `read` path is the author-blind primitive-with-`$id` shape the same file warns against at lines 166-171. → Say that only the `edit`/`delete` contexts route through `map_meta_cap()`; `read` checks the `read_private_<type>s` primitive directly (the recorded cap is still `read_private_shop_orders`, so audit output is unaffected).
- **[low]** `audit/references/audit-schema.md:97` and `audit/SKILL.md:182-186` — "Lint 6 FAILs a reference ability whose `input_schema.required` is non-empty" (presented as the qualifying rule) → `verify/references/schema-lints.md:82-97` has a second FAIL trigger: a *missing* `input_schema` (`WP_Ability::validate_input()` rejects `execute( array() )` with `ability_missing_input_schema`; confirmed at `wp-includes/abilities-api/class-wp-ability.php:519-533`). An auditor following the audit-side text could designate a schema-less zero-arg read and fail Lint 6. → Add "and must declare an `input_schema` (with `'default' => (object) array()`)" to both audit-side statements.
- **[low]** `verify/SKILL.md:93` "(Runtime only) Enumerate via REST + wp-cli" and `verify/SKILL.md:45` "Both modes produce the same structured report format" → `verify/references/runtime-harness.md` contains no REST/curl enumeration at all (wp-cli only, Check 1 lines 67-118) and adds a `## Runtime harness` report section (lines 468-511) that the SKILL.md template (lines 204-230) does not list. → Retitle step 3 to "via wp-cli" and add the runtime-only `## Runtime harness` section to the template (or mark it runtime-only).
- **[low]** `audit/references/capability-gate-tracing.md:232-236` — "WooCommerce's `shop_subscription` is registered with `capability_type='shop_order'`" → `shop_subscription` is not registered by WooCommerce core (`class-wc-post-types.php` trunk registers `product`/`shop_order`/`shop_coupon` families only; 0 matches for `shop_subscription`); it belongs to the WooCommerce Subscriptions extension, whose source could not be fetched (3× 404). → Attribute to WooCommerce Subscriptions and mark the cap-type value as an example to be confirmed in the target checkout.
- **[nit]** `audit/references/audit-schema.md:205,214` — minimal example is dated `2026-04-20` (`Last updated`, `audited_at`) yet populates `exposure` (added 2026-08-15, line 341), `use_case_fit`/`side_effects`/`seed_data_needs` and `backing.kind`/`permission.source` (added 2026-05-21, lines 333, 350). → Move the example dates to ≥ 2026-08-15.
- **[nit]** `verify/SKILL.md:135` — "the six shapes" → `verify/references/permission-roundtrip.md:35-43` classifies seven rows (A, B, B-bad, C, D, E, F); letters run A–F. → Write "shapes A–F (seven classifications, B has a B-bad variant)".
- **[nit]** `verify/references/annotation-correctness.md:32-34` — column titled "What it promises (from core)" gives readonly as "No durable writes to user / business state. GET-style side-effect-free." → core's docblock is "If true, the ability does not modify its environment." (`class-wp-ability.php:47`); the durable-writes/cache-exemption reading is the skill's own relaxation (lines 39-43). → Quote core verbatim and label the `set_transient`/timestamp allowance as skill policy.

## Verified correct

- **Annotation docblocks** — readonly "does not modify its environment"; destructive "may perform destructive updates … / performs only additive updates"; idempotent "calling the ability repeatedly with the same arguments will have no additional effect on its environment" (`class-wp-ability.php:46-59`); verify SKILL.md 42-43, 119-122 and annotation-correctness.md 35-36 paraphrase/quote accurately.
- **Core exposure resolution (7.1)** — `show_in_rest = show_in_rest ?? public ?? DEFAULT_SHOW_IN_REST`, `public ?? DEFAULT_PUBLIC` (`class-wp-ability.php:370-371`; `DEFAULT_PUBLIC` `@since 7.1.0`, line 34-37); non-bool `public` throws (346). WP 7.0 `prepare_properties()` has no `public` handling and `wp_parse_args` preserves the key (7.0 branch lines 319-333), supporting exposure-checks.md 22-25 "adapter honors `meta.public` on 6.9/7.0 where core ignores it".
- **Adapter exposure (0.6.1)** — `McpAbilityExposure::is_meta_public()`: explicit `mcp.public` cast `(bool)` wins, else strict `true === meta.public`, malformed `mcp` fails closed; class `@since 0.6.0` and docblock states the resolve-from-stored-ability rationale (`includes/Abilities/McpAbilityExposure.php:15-68`) — matches exposure-checks.md 3, 18-19, 65-71 and audit-schema.md 101-104.
- **`meta.mcp.type` promotion trap** — `McpAbilityHelperTrait::get_ability_mcp_type()` validates enum and returns `'tool'` (`McpAbilityHelperTrait.php:71-81`); `DiscoverAbilitiesAbility::execute()` lists anything the helper calls `'tool'` (`DiscoverAbilitiesAbility.php:97-100`); `DefaultServerFactory::discover_abilities_by_type()` compares raw `$meta['mcp']['type'] ?? 'tool'` with `!==` (`DefaultServerFactory.php:141-160`); `ExecuteAbilityAbility::check_permission()` gates on exposure only, never type (`ExecuteAbilityAbility.php:163-200`) — exposure-checks.md 54-63 and verify SKILL.md 150-153 correct.
- **Default-server `read` floor** — `HttpTransport.php:122`, `DiscoverAbilitiesAbility.php:140`, `GetAbilityInfoAbility.php:180`, `ExecuteAbilityAbility.php:226` all default to `'read'` (exposure-checks.md 116-122).
- **Enumeration surfaces** — `WP_Abilities_Registry::get_instance()` returns `null` with `_doing_it_wrong` before `init` (`class-wp-abilities-registry.php:282-294`); `get_all_registered()` (228-230); `wp_get_abilities()` always runs category/namespace/meta → `item_include_callback` → `wp_get_abilities_item_include` → `result_callback` → `wp_get_abilities_result` (`abilities-api.php` function body; filters at 549, 572, both `@since 7.1.0`); `meta` arg strict-matches (`_wp_get_abilities_match_meta`, 588-604) so `meta=>['public'=>true]` excludes mcp-only abilities (exposure-checks.md 129-135, 168-176; runtime-harness.md 67-118).
- **`_doing_it_wrong` sources** — invalid name (86-95), duplicate (97-105), unknown category (142-156), and `InvalidArgumentException` from `prepare_properties()` incl. missing/invalid `permission_callback` (registry 172-182; ability prepare_properties check) — exposure-checks.md 145-147, runtime-harness.md 107-110.
- **`execute()` order and hooks (7.1)** — `wp_ability_invoked` → `wp_pre_execute_ability` sentinel short-circuit returning the listener's value as-is (`class-wp-ability.php:783-812`) → `normalize_input` → `validate_input` → `check_permissions` → `ability_invalid_permissions` (814-840) → `wp_before_execute_ability` → `do_execute` (+`wp_ability_execute_result`, 701) → `validate_output` → `wp_after_execute_ability`; `wp_pre_execute_ability` absent in 7.0 (fetched file, no match). `check_permissions()`: `ability_invalid_permission_callback` (625), `wp_ability_permission_result` (652), non-bool/non-error coerced to `false`; `invoke_callback()` passes `$input` only when `input_schema` non-empty and converts `Throwable` to `ability_callback_exception` (585-604). permission-roundtrip.md 8-29, 48-72, 148-153, 175-199 and annotation-correctness.md 133 all correct.
- **Input validation edge cases** — `normalize_input()` substitutes only a root `default` (483-489); empty schema: `null` → `true`, anything else → `ability_missing_input_schema` with the exact message quoted in schema-lints.md 87-88 (519-533); REST run route resolves body `{}` → `null` and `{"input":{}}` → `array()` (`class-wp-rest-abilities-v1-run-controller.php:214-223`) — schema-lints.md Lint 6, runtime-harness.md 192-203, 311-335.
- **`/run` method enforcement** — `validate_request_method()`: readonly → GET, destructive && idempotent → DELETE, else POST, `rest_ability_invalid_method` 405 (run controller 110-132); routes `/wp-abilities/v1/abilities`, `/abilities/(?P<name>…)`, `/abilities/(?P<name>…?)/run` with `ALLMETHODS`, discovery gated on `current_user_can('read')` and forced `show_in_rest` (list controller 27-61, 90-102, 160, 180-193) — annotation-correctness.md 50-53.
- **Schema `format` lists** — PHP validator exactly `hex-color, date-time, email, ip, uuid` (`rest-api.php:2321-2344`; `uri` only in the sanitizer, 2947); JS `addFormats` exactly `date-time, email, hostname, ipv4, ipv6, uri, uuid` and compile-error catch returning "Invalid schema provided for validation." (`validation.ts:23-31, 202-207`); `#79555` "Abilities: Support URI schema format" listed under Gutenberg 23.6.0 Bug Fixes (`changelog.txt:1153, 1355`); `@wordpress/core-abilities` registers every `/wp-abilities/v1/abilities?per_page=-1&context=edit` result with `...ability` spread and `executeAbility()` validates input and output client-side (`core-abilities/src/index.ts:100-127`, `abilities/src/api.ts:197-231`) — schema-lints.md Lint 7. `additionalProperties:false` honored by core validator (`rest-api.php:2462-2470`); no `$ref` support in core validator.
- **`map_meta_cap` default rule** — quoted block matches `class-wp-post-type.php:610-620` verbatim (inside `set_props()`); defaults `capability_type => 'post'`, `capabilities => array()`, `map_meta_cap => null` (542-544); `get_post_type_capabilities()` branches only on the boolean, three meta caps unconditional, six mapping primitives + `_post_type_meta_capabilities()` conditional, `create_posts` aliases `edit_posts` (`post.php:2034-2081`); `map_meta_cap()` short-circuit appends raw `cap->edit_post`/`cap->delete_post` (`capabilities.php:139-145, 242-248`). WooCommerce's own `shop_order` opts in explicitly (`class-wc-post-types.php:464-465`) and `edit_others_shop_orders` is generated (`class-wc-install.php:2420-2430`).
- **`WP_REST_Posts_Controller` gates** — `get_items_permissions_check` only `edit_posts` under `context=edit` (160-172); `get_items()` per-row `check_update_permission`/`check_read_permission` (468-472); `get_item_permissions_check` edit-context update check then `check_read_permission` (580-611); `check_read_permission` → `current_user_can('read_post', $id)` (1784-1795); create: author→`edit_others_posts`, sticky→`edit_others_posts||publish_posts`, then `create_posts` (687-720); update: `check_update_permission` (`edit_post`) + same two branches (893-930); delete → `delete_post` (1065-1078); `sanitize_post_statuses` condition verbatim (3193-3215) — capability-gate-tracing.md 131-171, 217-226.
- **Implicit REST surface** — `create_initial_rest_routes()` loops `get_post_types/get_taxonomies( show_in_rest )` and registers posts, revisions, autosaves, terms controllers (`rest-api.php:265-313`); `get_rest_controller()` null for non-`WP_REST_Controller` class (`class-wp-post-type.php:869-893`), revisions null without `revisions` support (905-912), autosave null without `autosave` (944-951); `add_supports()` editor⇒autosave and default `title, editor, autosave` (676-701); autosaves collection `/(?P<id>[\d]+)/autosaves` GET+POST, item `/(?P<parent>…)/autosaves/(?P<id>…)` GET (`class-wp-rest-autosaves-controller.php:88-135`); revisions `/(?P<parent>…)/revisions[/(?P<id>…)]` (83-105); `rest_base`/`rest_namespace` fallbacks (`class-wp-rest-posts-controller.php:60-61`); settings gated on `manage_options` and `show_in_rest.name` renames the key (`class-wp-rest-settings-controller.php:67-68, 232, 263`) — controller-enumeration.md 79-136.
- **Commands** — `rg --multiline --pcre2 --type=php -n` (ripgrep 15.1.0 present); GNU grep BRE `\s*(` patterns; awk fence extractor works on the canonical example; wp-cli 2.12 global `--user=<id|login|email>` and `wp eval` confirmed via `wp cli param-dump` / `wp help eval`; PHP snippets use real APIs (`wp_get_ability`, `check_permissions`, `execute`, `get_meta`, `get_category`, `wp_create_user`, `set_role`, `wp_delete_user` after `wp-admin/includes/user.php`, `wpmu_delete_user` after `wp-admin/includes/ms.php`).
